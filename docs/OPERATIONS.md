# التشغيل والاستمرار

يعمل مُحاور على خادم مجاني، ونموذج مفتوح برصيد صغير مدفوع مسبقًا (لا فاتورة مفتوحة)، ولكل اعتماد حرج بديل جاهز.

## المكونات والبدائل

| المكون | الأساسي | البديل عند تعطله | التكلفة الحالية |
|---|---|---|---|
| الخادم | Oracle Cloud، الطبقة المجانية الدائمة، الرياض (2 OCPU، ذاكرة 12 GB) | لا خادم احتياطي: عند التعطل تُعاد الخدمة على Oracle، أو تُنشر الشيفرة نفسها على خادم آخر | 0 |
| النموذج اللغوي | DeepSeek V4.1 Flash عبر OpenRouter (`:nitro`: أسرع مضيف)، التفكير مغلق (`OPENAI_COMPAT_REASONING=off`)، وثماني قراءات ثانية في وقت واحد (`MUHAWIR_PARALLEL_CHECKS=8`) | gpt-oss:120b عبر Ollama Cloud (`OPENAI_COMPAT2_*`)، ثم Gemini، ينتقل إليهما النظام تلقائيًا | رصيد مدفوع مسبقًا بسقف إنفاق على المفتاح. مقيس في 6 أكتوبر على 24 جوابًا: نحو 16 طلبًا و51 ألف توكن إدخال و3 آلاف توكن إخراج للجواب الجديد، والسؤال المكرر يُجاب من التخزين بلا تكلفة. والبديلان ضمن حصصهما المجانية |
| بيانات المصادر | الموسوعة القرآنية، وhadith-api، وOpenITI، تُنزَّل عند بناء القاعدة | تبقى القاعدة المبنية تعمل إن تعذر التنزيل | 0 |
| شهادة HTTPS | Caddy وLet's Encrypt، باسم muhawir.duckdns.org (وعنوان sslip.io بديل للخادم نفسه) | تُجدَّد الشهادة تلقائيًا بـCaddy | 0 |

## القراءة الصوتية الاختيارية

- `AZURE_SPEECH_KEY`: مفتاح مورد Azure AI Speech؛ اتركه فارغًا لتعطيل الصوت العصبي.
- `AZURE_SPEECH_REGION`: منطقة المورد مثل `eastus`؛ يجب أن تطابق منطقة المفتاح. احفظ القيمتين في إعدادات الخادم فقط، ولا ترفعهما إلى المستودع.
- يرسل زر «استمع» نص الإجابة وحده إلى `/tts`، فيرسله الخادم إلى Microsoft بعد استبدال الآية المحصورة بين ﴿ و﴾ بعبارة «(آية)» أو `(verse)`. لا يرسل نص سؤال المستخدم. عند فقد الإعدادات أو فشل الخدمة يستعمل المتصفح صوت الجهاز.
- تحفظ ملفات MP3 في `data/tts-cache/` خارج Git؛ احمِ المجلد وامسح الملفات منه دوريًا عند الحاجة. تستهلك الأصوات العصبية حصة Azure Speech وقد تنشأ تكلفة بحسب خطة المورد.

## حصة النموذج (مقيسة)

- في أيام الاختبار استُعمل نحو 2,900 طلب، أي 77.9% من الحصة المجانية الشهرية في Ollama، فالحصة نحو 3,700 طلب في الشهر.
- السؤال الواحد يستعمل نحو 10–20 طلبًا: فهم الرسالة، والكتابة، وقراءة ثانية لكل جملة، والحكم على الصلة، وأحيانًا إعادة الكتابة.
- فالحصة المجانية تكفي نحو 185–370 سؤالًا في الشهر (تقدير من القياس). وما زاد عليها يذهب إلى Gemini، وحصته المجانية تتجدد يوميًا.
- للاستعمال الأوسع: خطة مدفوعة في Ollama أو Gemini بحسب أسعار كل مزود، مع سقف إنفاق شهري يضعه المشغّل.

## إن تعطل شيء

| العطل | ما يحدث |
|---|---|
| تعذر الوصول إلى النموذجين | يقول مُحاور «الخدمة غير متاحة مؤقتًا» ولا يعرض شيئًا غير مفحوص |
| توقف خادم Oracle | يتوقف مُحاور حتى يعود الخادم، فلا خادم احتياطي |
| نفاد رصيد OpenRouter أو تعطله | ينتقل تلقائيًا إلى Ollama ثم إلى Gemini |
| تعذر فحص الجواب | لا يُعرض الجواب (الفحص يفشل مغلقًا) |

## الصيانة

أدوات التشخيص المنقولة من الخادم إلى المستودع لا تعمل تلقائيًا: `scripts/selftest.py` يفحص البحث والقواعد دون نموذج، و`scripts/nightly.py` يُصدر تقريرًا تشخيصيًا دون استدعاء النموذج افتراضيًا. لا تعاد محاولة الأسئلة المخزنة إلا بتشغيله صراحةً مع `--retry --max 10`، وهو إجراء يستهلك رصيد النموذج. `scripts/check_dialects.py` اختبار يدوي يستدعي النموذج لكل حالة، فلا يُجدول. `scripts/forget.py` يعرض المطابقات أولًا ولا يحذفها إلا بخيار `--delete`؛ بعد الحذف تُعاد الخدمة لمسح النسخة الموجودة في الذاكرة.

| متى | ماذا |
|---|---|
| بعد كل تعديل | تشغيل الاختبارات الآلية، ثم على الخادم: `git pull` وإعادة تشغيل الخدمة |
| أسبوعيًا | فحص `/api/health`، واستهلاك الحصة في Ollama وGemini |
| شهريًا | التحقق من روابط جهات الإحالة في `muhawir/referrals.py` (الرئاسة العامة للبحوث العلمية والإفتاء) وأنها ما زالت تعمل، ثم إعادة بناء قاعدة المصادر (تطلب الموسوعة القرآنية إبقاء النسخ محدّثة)، وتحديث المكتبات، وإعادة التقييم |

## تحديث المتجهات بعد تغيير المصادر

### تجهيز اختبارات المصحف وفهرس USearch الاختياري على Oracle

بعد تحديث الشيفرة، شغّل الأداة من بيئة المشروع: `cd ~/muhawir && .venv/bin/python scripts/prepare_optional_assets.py`. إن غاب `usearch` تثبّته في البيئة الافتراضية. وتستخرج `mushafs-1.json.gz` من `data/dumps/mushafs-all.zip`، أو تنزّل الأرشيف الأصلي من quranpedia.net عند غيابه، دون إضافته إلى Git. وتبني `data/vectors.usearch` من المتجهات الموجودة دون إعادة تضمين النصوص أو طلب النموذج. يتطلب البناء وجود `vectors.npy` ومعرّفاتها واسم النموذج. يمكن استعمال `--no-download` لمنع تنزيل ملف المصحف تلقائيًا.

ثم تحقق من الاختبارين (لا يطلبان نموذج إجابة):

```bash
QURANPEDIA_MUSHAF="$PWD/data/dumps/mushafs-1.json.gz" .venv/bin/python -m pytest -q -rs tests/test_quranpedia.py tests/test_scalability.py
```

**بناء الفهرس لا يفعّله في الخدمة.** قارن الاسترجاع قبل تفعيله، بعد تحميل إعدادات الخادم، دون `--pipeline` لأنه يستدعي النموذج:

```bash
set -a; . "$HOME/muhawir.env"; set +a
HF_HUB_OFFLINE=1 MUHAWIR_VECTORS=1 MUHAWIR_VECTOR_INDEX=exact .venv/bin/python scripts/eval_retrieval.py > /tmp/muhawir-exact.txt
HF_HUB_OFFLINE=1 MUHAWIR_VECTORS=1 MUHAWIR_VECTOR_INDEX=usearch .venv/bin/python scripts/eval_retrieval.py > /tmp/muhawir-usearch.txt
```

راجع صف `keywords + vectors (RRF)` في الملفين، خصوصًا top 1/5/10 والوقت. لا تضف `MUHAWIR_VECTOR_INDEX=usearch` إلى `~/muhawir.env` ولا تعِد تشغيل الخدمة به إلا إذا كانت النتائج مقبولة؛ عند غياب الفهرس أو عدم تطابق بصمته يعود النظام تلقائيًا إلى البحث المتجهي الدقيق.

البحث بالمعنى (المتجهات) مفعّل على خادم Oracle بالإعداد `MUHAWIR_VECTORS=1` في `~/muhawir.env`. فهرس المتجهات مرتبط بقائمة المقاطع: إذا تغيرت المصادر وأُعيد بناء قاعدة البيانات، وجب بناء فهرس جديد، وإلا رجع البحث إلى الكلمات وحدها.

1. **بناء الفهرس على Kaggle** (معالج رسومي مجاني، نحو 90 دقيقة): دفتر `muhawir-notebook` بخلية واحدة تنزّل المستودع وتبني قاعدة البيانات والمتجهات، وتخرج `muhawir-vectors.tar.gz`. ملف «بينات» مرفوع في الدفتر مجموعةَ بيانات خاصة (Private)، لأن موقع dawa.center يمنع التنزيل الآلي. افتح الدفتر ثم Save Version ← Save & Run All، وتأكد في السجل أن عدد المقاطع يساوي عدد مقاطع الخادم.
2. **جلبه إلى الخادم بأمر واحد** (الخادم هو الذي يجلب الملف من Kaggle، فلا يُحفظ مفتاح الخادم في أي موقع خارجي):
   ```
   cd ~/muhawir && scripts/fetch_vectors.sh <اسم-المستخدم-في-Kaggle>/muhawir-notebook
   ```
   يتحقق الأمر من أن معرّفات المقاطع في الفهرس تطابق قاعدة البيانات واحدًا واحدًا وبالترتيب؛ فإن لم تتطابق لم يغيّر شيئًا. ويحفظ الفهرس السابق في `data/vectors.previous/`، ويعيد تشغيل الخدمة.
3. **مرة واحدة قبل أول استعمال:** في kaggle.com ← Settings ← API ← Create New Token، فينزل ملف `kaggle.json`. انسخه إلى الخادم:
   ```
   mkdir -p ~/.kaggle && mv kaggle.json ~/.kaggle/ && chmod 600 ~/.kaggle/kaggle.json
   ```
   هذا المفتاح يقرأ حساب Kaggle فقط، ولا يُرفع إلى المستودع.

وللإطفاء: اجعل السطر `MUHAWIR_VECTORS=` في `~/muhawir.env` ثم أعد تشغيل الخدمة؛ فيعمل مُحاور بالبحث بالكلمات وحده.

## الانتظار وعدد طلبات النموذج (نوفمبر 2026)

- **الانتظار:** إذا كانت كل أماكن الإجابة مشغولة (`MUHAWIR_ASK_CONCURRENCY`، الافتراضي 4)، يدخل السؤال صف الانتظار (`MUHAWIR_ASK_QUEUE_SIZE`، الافتراضي 12). تقول الصفحة فورًا «محاور يجيب أسئلة أخرى الآن، وسؤالك التالي…».
- **مدة الانتظار:** `MUHAWIR_ASK_QUEUE_TIMEOUT` صارت 45 ثانية بدل 10. الجواب الجديد يأخذ 15–25 ثانية، فكان كل من ينتظر 10 ثوانٍ تقريبًا يُرفض.
- **إعادة الكتابة:** لا تُعاد كتابة الجواب كاملًا لمجرد أن الفحص حذف ثلث جمله. تُعاد إذا حُذفت الجملة الأولى، أو نصف الجمل أو أكثر، أو قال الحكم إن الجواب لا يغطي السؤال («partly»). في الحالة الشائعة التي تُحذف فيها جملتان من ست ويبقى الجواب كاملًا، صار الجواب 11 طلبًا بدل 16.
- **السؤال المقترح بعد الجواب:** لم يعد في كل جواب، بل فقط حين تكون للسؤال خطوة تالية طبيعية في المقاطع. ولا يُقترح بعد جواب ناقص.
- **قراءة الجمل معًا (تجربة، مطفأة):** `MUHAWIR_CHECK_GROUPS=1` تجعل الجمل التي تستند إلى المقاطع نفسها تُقرأ في طلب واحد بحكم مستقل لكل جملة. ينزل الجواب المعتاد من نحو 9 طلبات إلى 5.
  - سُجّل سابقًا أن القراءة المجمّعة أكثر تساهلًا، فلا تُشغَّل قبل مقارنة مدفوعة بموافقة صاحب المشروع: `scripts/compare_check_groups.py questions.txt --max-questions 20 > check-groups.json` على الخادم.
  - تُشغَّل فقط إن كانت قائمة «accepted together, rejected alone» فارغة، أو راجعها إنسان ووجد كل حالاتها غير ضارة.
  - التقرير يحوي نص الجمل، فيبقى على الخادم ولا يُرفع.

## مُحاور عبر MCP (اختياري، مطفأ افتراضيًا)

يتيح لمساعدات ونماذج أخرى (Claude وChatGPT ونموذج محلي…) أن تبحث في مصادر مُحاور وتكتب الجواب بنموذجها هي. العنوان `https://muhawir.duckdns.org/mcp` (Streamable HTTP، بلا جلسات).

| الأداة | ماذا تفعل | التكلفة |
|---|---|---|
| `search_sources` | تبحث عن المقاطع لسؤال أو عبارة | بلا نموذج |
| `read_passage` | المقطع كاملًا مع ما قبله وما بعده | بلا نموذج |
| `find_quote` | أين يرد نص منقول في المصادر | بلا نموذج |
| `ask_muhawir` | جواب مُحاور المفحوص | نموذج مُحاور: مكان إجابة وحصة الأسئلة |

- **`MUHAWIR_MCP=1`** يشغّله. يحتاج حزمة `mcp` من `requirements.txt`، فنفّذ `pip install -r requirements.txt` بعد السحب.
- **`MUHAWIR_MCP_TOKEN`** يجعل كل طلب يحتاج الترويسة `Authorization: Bearer <القيمة>`، ويفتح `ask_muhawir`.
  - احفظه في `~/muhawir.env` فقط، ولا ترفعه.
  - بلا رمز تعمل الأدوات المجانية الثلاث لمن يعرف العنوان. ولا تعمل `ask_muhawir` إلا مع `MUHAWIR_MCP_ASK=1`، وهو غير مستحسن على عنوان عام لأنه يستهلك رصيد النموذج.
- **`MUHAWIR_MCP_PER_MINUTE`** (الافتراضي 120) حد لكل أدوات MCP معًا في الدقيقة.
- **`MUHAWIR_MCP_HOSTS=muhawir.duckdns.org`** يقبل الطلبات باسم الموقع وحده، حماية من DNS rebinding.
- **تعليمات للنموذج الخارجي:** يرسل الخادم تعليمات مختصرة: أجب من المقاطع وحدها، وانقل النص بلفظه، واذكر المصدر والموضع، وقل «لم أجد» إن لم تجب المقاطع، ولا تُفتِ في حالة شخصية.
- **التحقق:** لا يمكن التحقق من التزام النموذج الخارجي بها. جواب `ask_muhawir` وحده مفحوص جملة جملة.

## تحديث Oracle دون استهلاك رصيد النموذج

افحص `git status --short` قبل التحديث. إن وُجدت تعديلات في الشيفرة، احفظ نسخة مصدرية خارج المشروع ثم أخفِ الشيفرة مؤقتًا ضمن stash محدد المسارات. اترك `data/` كما هي؛ قاعدة المصادر وفهرس المتجهات ليسا جزءًا من Git. لا تستعمل `git clean` أو `reset --hard`، ولا تُعد تطبيق stash كله بعد السحب لأنه قد يعيد الشيفرة الأقدم فوق الإصلاحات الجديدة. إذا اعترض ملف غير متتبّع خارج المسارات المحددة (مثل `docs/RESULTS.md`)، انقله أولًا إلى نسخة احتياطية خارج المشروع.

```bash
set -e
cd ~/muhawir
tar -czf "$HOME/muhawir-source-before-update-$(date +%Y%m%d-%H%M%S).tar.gz" \
  --exclude='.git' --exclude='.venv' --exclude='data' --exclude='*.env' --exclude='*.db' \
  muhawir tests scripts .gitignore requirements.txt LICENSES.md
git stash push -u -m oracle-before-update -- muhawir tests scripts .gitignore requirements.txt LICENSES.md
git diff --quiet
git diff --cached --quiet
if [ -f docs/RESULTS.md ] && ! git ls-files --error-unmatch docs/RESULTS.md >/dev/null 2>&1; then
  mv docs/RESULTS.md "$HOME/muhawir-RESULTS-$(date +%Y%m%d-%H%M%S).md"
fi
git pull --ff-only origin main
.venv/bin/python -m pytest -q
sudo systemctl restart muhawir
sudo systemctl is-active muhawir
curl --fail --silent http://127.0.0.1:8000/api/health
sha256sum muhawir/pipeline.py
```

طابق `pipeline_revision` مع أول 12 حرفًا من بصمة `pipeline.py` في النسخة المسحوبة. تتغير البصمة عند تعديل هذا الملف؛ القيمة `10aedab0c0bb` تخص نسخة سابقة. إذا لم يطابقها رد الخدمة، تحقق من مسار `ExecStart` و`WorkingDirectory` في `systemctl cat muhawir`. يكفي فحص الصحة لتأكيد التحديث؛ لا ترسل سؤالًا إلى `/api/ask`.

حدود الأسئلة: `MUHAWIR_ASK_PER_MINUTE=60` و`MUHAWIR_ASK_CONCURRENCY=4` عبر جميع الزوار. الطلب المرفوض يعيد HTTP 429 قبل الوصول إلى النموذج. غياب قاعدة المصادر في وضع النموذج يوقف التشغيل بدل تقديم البيانات التجريبية؛ `MUHAWIR_ALLOW_SYNTHETIC=1` مخصص للتطوير الصريح فقط.

زر «توقف الانتظار» يلغي انتظار المتصفح؛ قد يستمر الطلب الذي بدأ على الخادم، لذلك لا يعني توقف تكلفة النموذج. الاختبارات في مهمة `Offline tests` تستعمل بيانات ومزودات وهمية ولا تستهلك رصيد النموذج.
