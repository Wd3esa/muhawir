# مسودة بلا تكرار — مرشح غير مفعّل

التغيير الوحيد: إضافة توجيه لتجنّب تكرار التعريف أو المعنى لمجرد تكراره في المصادر. التعليمات الأصلية والأمثلة وصيغة JSON باقية حرفيًا كبادئة، ولم تتغير STYLE_GUIDE أو أدلة السؤال أو فاحص الجمل. لا حذف أو دمج دلالي آلي في الشيفرة، ولا استدعاء إضافي لمراجعة التكرار.

هذه تجربة مختلفة عن #48: لا تحذف أمثلة المطالبة، ولا تسعى لتقليل طول التعليمات نفسها. زاد الإدخال قليلًا؛ المنفعة المحتملة تقليل جمل المسودة المتكررة وفحوصها اللاحقة، ولم تُقَس بعد. لا يُسمح بحذف دليل لازم أو شرط أو استثناء أو حكم رواية أو فرق بين أقوال، ولا بجمع تعريفات مختلفة ونسبتها إلى اتفاق. لا تكفي قلة الجمل وحدها للقبول.

## قبل الاختبار

المراجع هو baseline SYSTEM_PROMPT من commit a5f6fb2. يسجل manifest.json بصمات النصين، ولا يحمّل التطبيق candidate.txt. بقاء النص الأصلي حرفيًا لا يثبت ثبات سلوك النموذج بعد إضافة التعليمات.

اختبار التطوير الأول المقترح: سؤال التوكل بأدلته المثبتة للكشف عن تكرار التعريف، وسؤال الحول للتأكد من بقاء القيود والاستثناءات، وسؤال الجماعة للتأكد من بقاء الخلاف، وسؤال ذو جزأين للتأكد من اكتماله. لا تقليل للسياق في هذا الاختبار. يجب تثبيت الأدلة والأحكام المرجعية ومراجعتها، واختيار عدد التكرارات والمزود/الإعدادات والميزانية قبل أي طلب مدفوع.

يسجل القياس الإدخال والإخراج والكاش والوقت والكلفة المبلغة لكل محاولة، ثم أثر عدد الجمل على فحص المسار الكامل إن نجح تقييم المسودة. لا يستنتج الوفر من عدد الجمل وحده لأن retries والرفض وإعادة الكتابة قد تغيّره. تُرفض النسخة إذا حذفت قيدًا أو قولًا لازمًا أو أضعفت النسبة أو الامتناع، حتى لو كانت أرخص. لا قياس مدفوع جديد ولا نشر في هذا التغيير.

## الفحوص المحلية

استُخرجت المطالبة من AST وقورنت بصمتها بخط الأساس، وتحقق أن الأصل كاملًا بادئة المرشح. هذه فحوص سلامة إعداد التجربة فقط، ولا تختبر فهم النموذج أو موثوقيته. اختبارات تجهيز الأدلة الستة مستقلة عن هذا المرشح.

## مقارنة التطوير المجهزة

`comparison-spec.json` يثبت أربع حالات (R01/R04/R08/R06) ومعرّفات أدلتها ومواضعها وبصمات نصوصها ومعايير مراجعة مقترحة. لا يحتوي نصوص المصادر ولا موافقات بشرية. يظل هذا اختبار تطوير استكشافي، لا تقييم اعتماد، ولا تمر الحالات عبر بوابة المراجعة بوصفها معتمدة.

`scripts/prepare_nonredundant_plan.py` يقرأ قاعدة محلية مطابقة للبصمة، ويطابق النص والموضع وsource_id لكل مقطع، ثم يستعمل build_user_prompt الحقيقي لكتابة خطة خاصة. لا يولّد عبارات بحث ولا يستدعي نموذجًا. كل حالة تستعمل user prompt نفسه حرفيًا للنسختين، وترتيب النسختين متبادل بين الحالات. تحفظ خطة كاملة تتضمن النصوص بصلاحية 600 خارج Git.

`scripts/run_draft_comparison.py PLAN` يفحص الخطة بلا شبكة افتراضيًا. لا يعمل النقل إلا مع `--execute`: أربع حالات × نسختين = ثماني محاولات HTTP كحد أقصى؛ بلا إعادة محاولة أو مزود بديل. يسجل خطة العمل وبصمتها وبداية كل محاولة والرد والاستخدام والمضيف الفعلي والتكلفة في JSONL خاص مع flush/fsync. يتوقف عند فشل أو JSON غير صالح/مبتور أو كلفة مجهولة. لا تمحو الحالات الناقصة ولا تعاد تلقائيًا.

عتبة التوقف المقترحة `--stop-after-usd 0.10` تُفحص **بعد رد المزود**، وليست سقف إنفاق صارمًا: قد تتجاوزها كلفة آخر طلب وقد يتكلف طلب انتهى بمهلة. يلزم حد مستقل لدى المزود إن أُريد سقف مالي صارم. لا تغيير للمفتاح أو إعداده في هذه الأدوات. يلزم إذن صريح بالدفعة المدفوعة قبل التنفيذ؛ الموافقات السابقة تخص التجارب المنفذة بالفعل.

معيار المراجعة: تقارن الجمل بالدليل أولًا (النسبة، القيود، الاستثناءات، الرواية، الخلاف، اكتمال جزأي السؤال)، ثم تُعلّم مجموعات التكرار الدلالي. تكرار عدد من الكلمات وحده ليس تكرارًا، ولا تُحذف فروق الأقوال لتقليل عدد الجمل. عرض 8 طلبات لا يمثل ثمانية أسئلة مستقلة؛ هي أربعة أسئلة، بزوج واحد لكل منها. لا يمكن تقدير p95 موثوق أو تعميم الجودة منها. لا تتضمن الدفعة فاحص الجمل المدفوع أو قياس المسار الكامل؛ إذا استحقت المتابعة تُعد خطة مستقلة له، ولا تُحسب فحوصه ضمن هذه الثمانية.

اجتازت أدوات التجهيز والمقارنة 12 اختبار unittest محليًا بمزود وهمي ونصوص مصطنعة. هذه تختبر الحفظ ومنع الإعادة وعدد المحاولات وثبات السياق والتوقف عند الفشل والكلفة المجهولة، ولا تثبت جودة المرشح. ملفات الإنتاج الـ38 لم تتغير. لا تجربة مدفوعة جديدة أو تغيير خدمة ضمن هذا الإيداع.
