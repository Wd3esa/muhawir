Why combine two searches?

A toy example of reciprocal rank fusion (RRF). These are invented passage labels, not religious evidence.

04 / THE ENGINEERING DECISION

Why this approach?

For this product, an answer needs traceable religious evidence. Retrieval-augmented generation (RAG) gives the writer selected passages and keeps their IDs attached to claims. Python and FastAPI connect the pieces; SQLite and a small browser interface keep the first deployment manageable.

Why not a model alone?

It can produce fluent answers from memory without proving their source. RAG adds auditable evidence, but retrieval can still miss or misinterpret it.

Why not fine-tuning first?

Fine-tuning can teach style or behaviour. It does not replace a current source database or per-claim evidence. This project uses prompts and retrieval, not model training.

Why not only search?

A search engine shows passages with less generation risk. A writer helps with language, follow-ups and explanation; that extra capability requires extra checks and credit.

When should the stack change?

Many server replicas may need Redis, a shared database and durable monitoring. A larger interface may benefit from a framework. Introduce them for a measured need, then test the tradeoff.
